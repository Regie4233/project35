# Terrain Physics Collision Findings & Resolution

This document summarizes the investigation and fixes applied to the voxel terrain collision system, resolving the issue where the physics-enabled sphere (`Spherex`) fell through the procedurally generated Marching Cubes terrain, and fixing a subsequent compilation error.

---

## 1. Summary of Issues & Diagnoses

### Issue A: Sphere Passes Directly Through the Terrain
* **Symptom:** When entering Play Mode, the `Spherex` entity fell straight through the generated terrain, triggering the safety reset under $Y < -50$.
* **Diagnosis 1 (Mesh Winding):** The triangles generated by the Marching Cubes algorithm in `MarchingCubesJob.cs` had backward winding. This meant the collision normals faced downwards/inwards. Since Unity Physics colliders are single-sided by default, the sphere falling from above did not register a collision.
* **Diagnosis 2 (Unregistered Physics Entity):** The procedurally generated chunk entities lacked a `PhysicsWorldIndex` component. In Unity ECS Physics (DOTS), a static collider must have this component to register in the broadphase physics world simulation. Without it, the physics engine ignored the colliders entirely.

### Issue B: Compilation Error `CS0315` in `ChunkGenerationSystem.cs`
* **Symptom:** Adding the `PhysicsWorldIndex` to register the collider caused a compilation failure:
  > `error CS0315: The type 'Unity.Physics.PhysicsWorldIndex' cannot be used as type parameter 'T' in the generic type or method 'EntityManager.AddComponentData<T>(Entity, T)'. There is no boxing conversion from 'Unity.Physics.PhysicsWorldIndex' to 'Unity.Entities.IComponentData'.`
* **Diagnosis:** `PhysicsWorldIndex` implements `ISharedComponentData` (shared component data), not `IComponentData`. Calling `AddComponentData` is invalid for shared components.

---

## 2. Solutions & Fixes Applied

### Fix 1: Correct Winding and Double-Sided Colliders
1. **Winding Correction (`MarchingCubesJob.cs`):**
   Corrected the vertex layout sequence to guarantee faces wind clockwise relative to the air side.
2. **Double-Sided Geometry (`ChunkGenerationSystem.cs`):**
   Modified the collider generation to duplicate all triangles with flipped winding. This ensures robust collisions regardless of which direction an object approaches the surface:
   ```csharp
   // Duplicated indices with reverse winding for double-sided collisions
   int triCount = indices.Length / 3;
   for (int i = 0; i < triCount; i++)
   {
       int idx = i * 3;
       indices.Add(indices[idx]);
       indices.Add(indices[idx + 2]);
       indices.Add(indices[idx + 1]);
   }
   ```

### Fix 2: Shared Component World Registration (`ChunkGenerationSystem.cs`)
Replaced `AddComponentData` with `AddSharedComponent` to properly assign the shared component type:

```diff
- if (!EntityManager.HasComponent<PhysicsWorldIndex>(item.entity))
- {
-     EntityManager.AddComponentData(item.entity, new PhysicsWorldIndex { Value = 0 });
- }
+ if (!EntityManager.HasComponent<PhysicsWorldIndex>(item.entity))
+ {
+     EntityManager.AddSharedComponent(item.entity, new PhysicsWorldIndex { Value = 0 });
+ }
```
